# 📚 로컬 RAG 챗봇 (Ollama)

내 PC에서만 돌아가는 문서 기반 질의응답 챗봇입니다. 문서를 올리면 관련 내용을 검색(Retrieval)해서, 그 근거로 로컬 LLM이 답변(Generation)을 만듭니다. 인터넷이나 외부 API를 쓰지 않으므로 문서와 질문이 PC 밖으로 나가지 않습니다.

- **LLM / 임베딩:** [Ollama](https://ollama.com) — `qwen3:8b`(답변), `bge-m3`(임베딩)
- **검색:** 한국어 2-gram BM25 + 임베딩 하이브리드 (RRF 결합)
- **저장:** SQLite 파일 하나 (`data/rag.db`)
- **화면:** FastAPI + 순수 HTML/JS, 답변마다 검색 근거 표시

## 구조

```
 문서(PDF/DOCX/TXT/MD)
    │ 1. 텍스트 추출 (pypdf, python-docx)
    ▼
 2. 청크 분할 ── 문단 단위, 약 600자, 120자 겹침
    │
    ├──▶ 3-1. BM25 색인 (한국어 글자 2-gram)
    └──▶ 3-2. 임베딩 (Ollama bge-m3) ──▶ SQLite에 저장
                                   
 질문 ──▶ 4. 하이브리드 검색: BM25 순위 + 코사인 유사도 순위 → RRF로 결합 → 상위 k개
                │
                ▼
          5. 프롬프트 = 시스템 지시 + <context>검색된 조각</context> + 질문
                │
                ▼
          6. Ollama (qwen3:8b) → 답변 + [출처]
```

| 파일 | 역할 |
|---|---|
| `app/rag.py` | 추출, 청크 분할, BM25, 임베딩, 하이브리드 검색 |
| `app/chat.py` | 프롬프트 구성, Ollama 호출, 출처 추출 |
| `app/ollama.py` | Ollama HTTP 클라이언트 (`/api/chat`, `/api/embed`) |
| `app/store.py` | SQLite 저장소 |
| `app/main.py` | 웹 서버 (업로드, 채팅, 검색 API) |
| `cli.py` | 명령줄 등록·검색·질문 |
| `eval.py` | 검색 품질 평가 (Hit@k, MRR) |

## 설계 포인트

**1. 한국어 키워드 검색: 글자 2-gram BM25**
한국어는 조사와 어미가 붙어 "보강은", "보강을", "보강" 이 모두 다른 단어가 됩니다. 형태소 분석기 대신 글자 2개씩 자르면(`보강은` → `보강`, `강은`) 설치 없이도 이 변화를 흡수합니다. 평가에서 "~하나요?", "~있나요?" 같은 질문 어미가 FAQ 문서로 결과를 쏠리게 하는 문제를 발견해, 어미 2-gram을 불용어로 뺐습니다. (아래 평가 참고)

**2. 의미 검색: bge-m3 임베딩**
"셔틀버스 있나요?" ↔ "차량 운행", "면담" ↔ "상담"처럼 단어가 전혀 겹치지 않으면 BM25는 찾지 못합니다. 다국어 임베딩 모델 bge-m3로 의미가 가까운 조각을 찾아 보완합니다.

**3. 하이브리드 결합: RRF (Reciprocal Rank Fusion)**
두 검색의 점수 단위가 달라 직접 더할 수 없으므로, 순위만 사용해 `score = Σ 1/(60 + rank)`로 합칩니다. 정확한 단어 일치와 의미 유사성을 함께 반영합니다.

**4. 환각 억제**
시스템 프롬프트로 "검색된 문서에 없는 사실은 지어내지 말고 찾지 못했다고 답하라"고 지시하고, 근거 문서 제목을 `[출처]`로 붙이게 합니다. 화면에서 실제 검색된 조각을 함께 보여줘 답변을 검증할 수 있습니다.

**5. 로컬 모델 운영**
- Ollama 기본 문맥 길이(2~4K)는 검색 자료가 잘려 들어가므로 `num_ctx=8192`로 늘렸습니다.
- qwen3의 추론 출력은 `think: false`로 끄고, 혹시 섞여 나오는 `<think>` 태그도 제거합니다.
- 임베딩 서버가 꺼져 있어도 BM25만으로 동작하고, 임베딩 모델을 바꾸면 자동으로 다시 계산합니다.

## 실행 방법

```bash
# 1) Ollama 설치 후 모델 받기
ollama pull qwen3:8b        # 메모리가 부족하면 qwen3.5:2b (.env의 OLLAMA_MODEL도 변경)
ollama pull bge-m3

# 2) 파이썬 환경
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env

# 3) 예시 문서 등록 → 검색 평가 → 질문
python cli.py ingest sample_docs/*.md
python eval.py
python cli.py ask "아이가 아파서 결석했는데 어떻게 하나요?"

# 4) 웹 화면
uvicorn app.main:app --port 8000      # http://localhost:8000
```

## 검색 평가

질문마다 정답 문서가 상위 k개 안에 들어오는지 측정합니다. 질문은 문서와 일부러 다른 표현으로 썼습니다.

### 1차: 학원 운영 문서 3개, 질문 10개

| 단계 | Hit@1 | Hit@3 | MRR |
|---|---|---|---|
| BM25 (2-gram) | 50% | 90% | 0.700 |
| BM25 + 어미 불용어 | 70% | 80% | 0.750 |
| 하이브리드 (+ bge-m3) | **90%** | **100%** | **0.950** |

- 어미 불용어로 "~하나요?" 질문이 FAQ 문서로 쏠리던 문제가 줄어 Hit@1이 올랐습니다.
- 키워드만으로 못 찾던 "면담"↔"상담", "셔틀버스"↔"차량 운행"을 임베딩이 찾아냈습니다.
- 남은 오답 "아이가 아파서 수업에 못 갔어요"는 정답 문서가 2위로, "어떻게 하나요?" 형태의 FAQ 문서가 여전히 1위에 옵니다.

### 2차: 학습코칭 문서 3개 추가 (문서 6개, 질문 16개)

학원 운영 안내만으로는 답이 짧은 사실 확인 질문뿐이라, 학생·학부모가 자주 묻는 학습코칭 가이드(`시험_대비_계획`, `오답노트_작성법`, `공부_습관_코칭`)를 직접 작성해 추가했습니다.

| 단계 | Hit@1 | Hit@3 | MRR |
|---|---|---|---|
| BM25 + 어미 불용어 | 56% | 81% | 0.679 |
| 하이브리드 (+ bge-m3) | **75%** | **100%** | **0.865** |

- 문서가 늘어나자 키워드 검색은 크게 흔들렸습니다. "중학생 영어 수업 시간"이 '중학생' 단어가 있는 코칭 문서로 가는 등, 주제가 다른 문서끼리 단어가 겹치기 시작했습니다.
- 하이브리드는 모든 질문에서 정답을 3위 안에 찾았습니다.
- 남은 Hit@1 오답은 주제가 실제로 겹치는 경우입니다. 예를 들어 "시험 대비 수업이 있나요?"(학원 특강 안내)와 시험 대비 계획(공부법)은 둘 다 '시험 대비'를 다룹니다. 다음 단계로 재순위 모델이나 문서 분류(운영 안내/학습코칭) 필터를 시험해 볼 수 있습니다.

### 답변 확인 (qwen3.5:2b)

| 질문 | 답변 | 확인한 점 |
|---|---|---|
| 결석하면 보강 받을 수 있어? | 2주 이내 신청, 질병 결석은 진단서 없이 가능 · 출처 `학원_운영_규정` | 규정을 정확히 인용 |
| 오답노트 어떻게 써? | 4단계(문제·틀린 이유·바른 풀이·다음에 할 일) · 출처 `오답노트_작성법` | 코칭 문서 검색 |
| 수능 1등급 컷이 몇 점이야? | "등록된 문서에서 찾지 못했습니다." | 문서에 없는 내용은 지어내지 않음 |

모델이 출처를 `[학원 운영 규정]`처럼 띄어 쓰는 경우가 있어, 출처를 맞출 때 공백과 밑줄을 무시하도록 고쳤습니다.

## 한계와 개선 방향

- 문서가 많아지면 청크 크기, 상위 k 개수, RRF 상수를 평가로 다시 맞춰야 합니다.
- 스캔 이미지 PDF는 OCR이 필요합니다. HWP는 PDF로 변환해서 올려야 합니다.
- 재순위(re-ranking) 모델을 추가하면 상위 결과의 정확도를 더 올릴 수 있습니다.
- 2B~8B급 로컬 모델은 긴 문서 요약이나 복잡한 추론에서 큰 모델보다 약합니다.
