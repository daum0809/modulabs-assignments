# 사장님 도입 체크리스트 (STEP 13 확장)

카드뉴스 앱의 흐름(자료 조사 → 후보 비교 → 사람의 선택 → 결과물 → 근거 검수)을 **"자동화 프로그램을 사장님 가게에 들일 때 확인할 것"**을 정리하는 일에 옮긴다. 새 앱을 만들지 않고, 같은 앱에서 프로젝트를 만들 때 **만들 것: 사장님 도입 체크리스트**를 고르면 된다.

## 해결할 불편

내가 만든 자동화 프로그램(예: 강사료 자동 계산)을 다른 사장님께 소개하면 "그래서 우리 가게는 뭘 준비해야 해요?"라는 질문을 매번 받는다. 그때마다 README와 코드를 다시 읽고 준비물·순서·주의점을 손으로 정리한다.

## 13-1. 바꿀 부분

| 설계할 부분 | 정할 내용 | 이 작업에서 |
|---|---|---|
| 입력 | 사용자가 무엇을 넣는가 | 자동화 프로그램 자료 폴더(README·코드), 주제, (선택) 가게 상황(예: "강사 5명인 영어학원") |
| AI 판단 | 무엇을 추리고 비교·제안하는가 | 자료에서 **이 프로그램이 줄여 주는 반복 업무 후보**를 뽑고, 후보마다 근거 파일·자료가 충분한지·불확실한 점을 표시 |
| 사람 결정 | 목표·취향에 따라 달라지는 곳 | 어떤 반복 업무로 체크리스트를 만들지 고르기. 가게 상황이 결과를 크게 바꿀 때만 짧게 묻기(이미 적었으면 다시 묻지 않음). **자료가 부족하면 자료를 더 넣을지, 부족한 대로 빈칸을 표시할지** 묻기 |
| 도구 행동 | 선택 뒤 실제로 무엇을 검색·작성·저장하는가 | 자료 폴더를 다시 읽어 **준비물 / 도입 순서 / 주의할 점** 체크리스트 작성, 항목마다 근거(파일·줄 또는 공식 링크). 법·세금은 공식 자료와 대조 |
| 검수와 산출물 | 어떤 상태면 쓸 수 있는가 | 항목마다 근거가 **실제로 읽은 파일·원문**에 있는지 앱이 대조(✅ 근거 확인 / ⚠ 근거 없음). 자료에 없는 것은 '자료에 없음'으로 따로 모음. 결과를 Markdown 파일로 내려받기 |

## 카드뉴스 PRD에서 가져온 것 / 바꾼 것

| 가져온 것 | 바꾼 것 |
|---|---|
| 프로젝트·작업·세션 저장, 질문 대기(`waiting_for_user`)와 이어가기, 중복 요청 막기, 서버 재시작 복구 | 결과물: 카드 PNG → **체크리스트 문서** (스토리보드·그림·렌더링 단계 없음) |
| 넓은 조사 → 1~3개 고르기 → 심층 판단 | 후보: 소식 → **반복 업무 후보** |
| 근거 없는 효과·수치 금지, 운영자 경험은 주장으로 표시 | 검수: 항목마다 근거가 실제로 읽은 파일에 있는지 **앱이 대조** |
| 자료 폴더는 `--add-dir`로 읽기만 | 자료 부족 시 **추가 자료 폴더**를 답변으로 받아 다음 호출에 함께 넘김 |

## 수용 조건

1. 만들 것을 고르는 칸이 있고, 체크리스트 프로젝트에는 스토리보드·그림 단계가 나오지 않는다.
2. 후보마다 근거 파일과 '자료 충분/부족'이 보인다.
3. 체크리스트 항목마다 근거가 있고, 앱이 실제로 읽은 파일과 대조해 ✅/⚠를 표시한다.
4. 자료가 부족하면 그럴듯하게 채우지 않고, 부족한 점을 보여 주며 자료를 더 넣을지 묻는다. 추가 자료 폴더를 답하면 그 폴더도 읽어 다시 만든다.
5. 결과를 Markdown으로 내려받을 수 있고, PC 경로는 자료 폴더 기준 상대 경로로 바뀐다.
6. 정상 입력 1번, 자료 부족 입력 1번을 실제 엔진으로 실행해 기록한다.
