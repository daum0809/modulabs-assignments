# STEP 1. 카드뉴스 형식 가설 (조사 전)

작성일: 2026-10-23
주제: 모두연에서 배운 수업 하나씩 → 사장님을 위한 자동화 프로그램
(카드뉴스 한 편 = 수업 하나 + 그 수업으로 만든 자동화 하나)
오늘 제출 범위: 카드뉴스 **한 편**만 만든다. 나머지 수업은 다음에 이어서 만든다.

> 조사 전 가설입니다. 3절에서 PRD에 반영하고, 5절에서 실제 수업·자동화를 고른 뒤 5.3에서 다시 판단합니다.

## 독자

작은 가게·회사를 운영하는 사장님. 코딩은 모르지만 반복 업무(예약 확인, 주문 정리, 고객 응대, 매출 집계 등)에 시간을 많이 쓰는 사람.
읽고 나서 할 행동: "이 자동화를 우리 가게에도 써 볼까?" 판단하고, 첫 단계를 따라 해 본다.

## 고른 형식 두 개

| 형식 | 어떤 독자에게, 왜 |
|---|---|
| 이야기형 | 자동화가 왜 필요한지 아직 와닿지 않는 사장님에게 맞음. 반복 업무 상황 → 불편 → 자동화로 바뀐 점 → 활용 → 한계 순서라 "우리 가게 이야기"처럼 이해하기 쉬워서. |
| 단계 안내형 | 이미 써 보고 싶은 사장님에게 맞음. 준비물 → 1단계 → 2단계 → 결과 확인처럼 카드마다 동작 하나를 보여 줘서 처음이어도 따라 할 수 있어서. |

## 편집 규칙 (3절에서 PRD와 비교할 것)

- 두 형식을 비교해 하나를 추천한다.
- 수업 내용과 자동화 결과는 실제 수업 자료·실행 결과로 뒷받침한다(날짜, 수업 이름 표기).
- 확인하지 않은 효과(예: "업무 시간 절반")는 후킹 문장에 넣지 않는다.
- 독자나 후킹 방향에 따라 결과가 크게 달라질 때만 짧은 선택지로 묻고, 이미 명확한 독자는 다시 묻지 않는다.

## 이미지 기록 규칙

- '저작권 없음'으로 묶지 않고 **CC0·퍼블릭 도메인 / 라이선스 허용 스톡 / 생성 이미지**로 나눠 출처와 사용 조건을 기록한다.
- 생성 이미지는 사용한 도구(agy / claude cli)와 그 조건을 기록한다.
- 생성한 그림을 실제 프로그램 화면이나 가게 사진처럼 표시하지 않는다. 실제 화면은 직접 캡처한 것만 쓴다.

## 앱에 줄 편집 방향 예시 (STEP 10에서 사용)

> 코딩을 모르는 사장님에게 모두연에서 배운 수업 하나로 만든 자동화 프로그램을 소개하고 싶어. 수업 이름과 날짜를 확인하고, 이야기형과 단계 안내형을 비교해 추천한 뒤 카드 순서를 제안해 줘.
