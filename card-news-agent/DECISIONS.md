| 그림 버전 | 다시 만들면 `card-NN-v(K+1)`로 새 파일, 이전 파일 보관 | PRD 6절: 수정 범위 밖 카드가 바뀌지 않게 버전 보관 |
| 스토리보드 변경 | 승인 전까지만 변경 요청 가능, 버전이 1씩 올라가고 승인은 화면이 본 버전과 같아야 함 | 오래된 화면에서 승인하는 것을 막는다 |
| 도형 그림 호출 | 프로젝트 대화와 따로(`--no-session-persistence`), 도구 없이 | 그림 그리기가 조사·원고 대화를 어지럽히지 않게, 파일·웹 접근도 필요 없음 |

## STEP 8. 글자 넣기 — 구현상의 기본안 (2026-10-23)

| 항목 | 기본안 | 이유 |
|---|---|---|
| 렌더러 | **이 PC의 Chrome(없으면 Edge) 헤드리스**로 카드 HTML을 1080×1350 PNG로 찍음 | 설치할 것이 없다(Pillow 불필요). 한글 글꼴·줄바꿈·SVG·JPEG를 모두 그대로 처리. STEP 7에서 "렌더러는 STEP 8에서 묻는다"고 적었으나, 사용자가 "최대한 예쁘게, 오늘 안에 빨리"를 원해 설치가 필요 없는 쪽으로 정함 |
| 글자 크기 | 자동 맞춤: 기본 → 제목 줄이기 → 글자 뒤 반투명 상자. 사용자가 크기를 정하면 그대로 | 그림마다 비어 있는 위쪽 여백이 달라서 같은 크기로는 겹친다(실제로 7장 모두 겹침) |
| 검사 | 글자 아래 끝(여백 620px, 상자일 때 1230px), 긴 단어, 글자 영역의 대비(10% 지점이 4.5:1 미만이거나 대비 3 미만 점이 3% 초과면 경고), 휴대폰 375px에서 본문 12px 미만 | PRD 5절: 잘림·대비·휴대폰 가독성 확인. '10% 지점'만으로는 작은 겹침을 놓쳐서 비율 기준을 더함 |
| 그림 비율 | `object-fit: cover`로 4:5에 맞춰 가운데 기준으로 자름 | agy 그림이 3:4(896×1200)라서 |
| 그림 출처 표시 | 카드 오른쪽 아래에 "AI 생성 그림 (Antigravity)" / "AI 도형 그림 (Claude CLI)" | PRD: 생성 이미지를 실제 화면·사진으로 오해하지 않게 |
| 다시 만들기 실패 | 이전 그림을 유지, 실패는 `lastAttempt`에 기록 | 실제로 카드 7에서 이전 그림이 사라진 사례 |

## 공개 범위와 글 (사용자 결정, 2026-10-23)

| 항목 | 결정 | 이유 |
|---|---|---|
| 카드뉴스에 쓰지 않을 것 | 로그인 방식, 비밀번호·체험번호, 저장 방식·시간, 계산 방법, 코드·파일 이름, 기술적 약점 | 사용자: "프로그램 짜는 내용을 다 오픈할 필요는 없다". 보안상으로도 공개하지 않는 편이 맞다 |
| 글 길이 | 한 장에 제목 + 한 줄, 소비자(원장님) 입장 | 사용자: "글자 수가 많다". 휴대폰에서 넘겨 보는 형식 |
| 장 수 | 7장 → **6장** (주휴수당 카드를 '얻는 것' 카드에 합침) | 사용자 선택(B). 그림은 다시 만들지 않고 재사용 |
| 마무리 디자인 | 앱 결과를 제출용으로 두고, 같은 글로 **Canva 디자인**을 따로 만든다 | 사용자: "Canva 같은 디자인 툴이 퀄리티가 좋을 것" |

## STEP 9 — 구현상의 기본안

| 항목 | 기본안 | 이유 |
|---|---|---|
| 최종 승인 | 카드 번호·PNG·글로 만든 서명에 묶음. 하나라도 바뀌면 자동으로 풀림 | PRD: 수정하면 승인 해제, exports는 최종 승인된 버전만 |
| 요청문 고치기 | 글만: 엔진이 그 카드 글만 고침(도구 없이, 프로젝트 대화와 따로). 그림만: 수정 요청을 그림 요청문에 붙여 그 카드만 | 교안: 카드 번호 + 문제 + 원하는 결과로 콕 집어 고치기, 고치지 않은 카드는 그대로 |
| 내보낸 파일 검증 | ZIP을 직접 열어 검사. 링크·뜻·법 내용·휴대폰 읽기는 '확인 못 함' | 교안: 확인하지 못한 항목은 통과로 처리하지 않는다 |
