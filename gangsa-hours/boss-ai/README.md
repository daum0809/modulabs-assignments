# 하루질문 OS · 사장 문제해결 AI PoC

마음 체크인 → 고민을 한 문장으로 → 우선순위 하나 → 오늘 첫 30분 → 저녁 회고.

노션에 정리된 사용자 고유의 하루질문 OS 구상을 기준으로 구현했습니다. 매출 고민을 첫 실험 범위로 삼습니다. [기획 반영 내역](DESIGN_NOTES.md)을 참고하세요.

**개발 블로그:** [하루질문 OS 개발 기록](http://yonsei-academy.kr/gangsa-hours/boss-ai/)

**가상 사례 데모:** [체험 화면](http://yonsei-academy.kr/gangsa-hours/boss-ai/demo.html) — 모델 실호출이 아닌 사전 작성 예시입니다.

2026-09-22 GitHub Pages 배포 성공 및 블로그 HTTP 200 응답을 확인했습니다.

## 현재 상태
- 공개 웹: 블로그와 사전 작성 가상 사례 3종. 실제 AI 추론이 아님.
- 실제 AI 코드: `server.py`에서 OpenAI Responses API를 호출함. 키는 환경변수로만 읽음.
- 실제 모델 호출·성능 검증: **미실행**. 작업 환경에 API 키 없음.
- 테스트 통과는 API와 모델 성능 검증을 의미하지 않음.
- 실제 사업 정보나 개인정보는 저장소에 올리지 말 것.

## 문제 정의 (평가 1)
대상: 소규모 서비스업 대표. 고민은 있으나 매출 하락을 유입/전환/객단가/재구매로 분해하기 어려운 상황.
기존 방식: 포괄적인 질문 한 번으로 일반적 조언을 받음.
가설: 필요한 정보를 먼저 묻고 근거와 가설을 분리하면 실행 과제의 구체성과 근거 일치성이 개선될 것이다.
범위: 원인 확정이나 경영성과 보장이 아닌, 검증할 가설과 다음 행동 제안.
성공 목표(미달성/미측정): 일반 프롬프트 대비 10점 평가 평균 +2점; 근거 없는 수치 생성 0건; 응답 형식 성공 95% 이상. 사용성 목표: 5분 안에 행동 계획 1개 완성. 목표는 성과 아님.

## 모델·기법 (평가 2)
초기 구현 모델: `gpt-4.1-mini-2025-04-14`. 한국어 질문 생성과 구조화 출력 지원을 확인하기 위한 후보이며 최적 모델이라는 주장은 하지 않음.
규칙 기반만으로 자유 서술을 해석하기 어렵고, 초기 학습 데이터가 없어 파인튜닝은 하지 않음.
기법: 단계별 프롬프트, JSON Schema Structured Outputs, 최대 3개 질문, 사실/가설/한계 분리.
노션의 5단계 질문·실행 순환을 프롬프트와 화면 흐름에 반영함. 원문 검색·RAG·파인튜닝은 사용하지 않음. 완전 자율 에이전트가 아닌 사용자가 제어하는 2단계 워크플로.
[모델 문서](https://developers.openai.com/api/docs/models/gpt-4.1-mini) · [구조화 출력](https://developers.openai.com/api/docs/guides/structured-outputs)

## 실행 (평가 3)
Python 3.10 이상. 별도 패키지 없음. 저장소 ZIP을 다운로드하거나 clone한 후 이 폴더로 이동.
PowerShell에서 키를 기록에 남기지 않고 입력:
```powershell
$bossSecret = Read-Host 'OpenAI API key' -AsSecureString
$env:OPENAI_API_KEY = [System.Net.NetworkCredential]::new('', $bossSecret).Password
python server.py
```
브라우저: http://127.0.0.1:8765/demo.html
실행 방식에서 실제 AI 선택 → 익명/가상 고민 입력 → 질문 생성 → 답변 입력 → 진단 결과.
종료는 Ctrl+C. 종료 후 `Remove-Item Env:OPENAI_API_KEY`.
키가 없으면 예시 모드만 사용 가능. 키를 채팅·HTML·GitHub에 붙여 넣지 말 것. API 호출은 사용자 API 계정에 과금될 수 있음. 모델 접근 불가 시 계정에서 지원하는 모델을 OPENAI_MODEL로 설정하고 모델명을 검증 기록에 남길 것.
서버는 127.0.0.1에만 바인딩. 공개 서버용 인증/사용량 제한은 없으므로 인터넷에 직접 노출하지 말 것. GitHub Pages는 이 Python 서버를 실행하지 않음.

## 효과 검증 (평가 4)
`python -m unittest discover -s . -p 'test_*.py'` — 실호출 없는 테스트.
`python evaluate.py --live` — 가상 사례 6건 × 질문/진단/일반 프롬프트 3회 = 18회 실제 API 호출. 비용 발생. 결과는 results/에 저장되며 공개 저장소에 커밋하지 않는다.
동일 모델·동일 사례·동일 정보량으로 구조화 진단과 일반 프롬프트 결과를 비교한다. 질문 생성은 별도로 측정하며, 최종 비교는 같은 정답 정보(followup)를 제공해 정보량 차이를 통제한다.
측정: 응답 시간, 토큰 사용량, JSON 구조 성공 여부. 품질은 results/review.csv에 2인 평가 권장, 각 조건명 가리고 무작위 순서로 평가.
품질 0~2점씩: 사실 일치 / 불확실성 표시 / 가설 판별 가능성 / 행동 구체성 / 제약 반영. 10점 합산. 근거 없는 숫자는 별도 기록.
가상 데이터이므로 일반화·실제 매출 개선을 입증하지 않음. 사람의 과제 완료 시간은 별도 사용성 실험으로 측정. AI가 평가 점수를 스스로 높게 주는 방식은 사용하지 않음.
모든 결과는 **미측정**이며 스크립트 실행 후에만 업데이트한다.

## 한계와 다음 시도 (평가 5)
모델 환각, 자기보고 오류, 소표본, 인과관계 미확인. Schema 준수가 내용의 정확성을 보장하지 않는다.
실행 상태·장애물·회고 기록, JSON 내보내기, 같은 화면에서 회고를 다음 체크인으로 옮기기를 지원. 실제 AI 모드는 이전 회고를 다음 질문에 전달한다. 새로고침 후 자동 복원·JSON 가져오기·공유 DB는 아직 지원하지 않는다.
다음 순서: 실호출 검증 → 동일 사례 비교 → 대표 사용자 3~5명 사용성 시험 → 원본 질문집을 공개하지 않는 검색 기반 참고자료 연결.

## 5단계 체험 방법
1. 마음 한 단어·강도·시작 시간을 선택하고 고민을 입력합니다.
2. 확인 질문 최대 3개에 답합니다.
3. 오늘 집중할 문제 한 문장과 자기보고 사실/검증 전 가설을 확인합니다.
4. 오늘 30분 이내 첫 행동 하나를 검토합니다.
5. 실제 실행 후 상태·장애물·회고를 적고 JSON으로 저장하거나 다음 체크인으로 옮깁니다.

가상 모드는 결과가 고정되어 있어 체크인과 회고가 결과에 영향을 주지 않습니다. 감정 강도는 자기보고이며 심리검사가 아닙니다.
