# Main Quest 2 문제 정의서

## 도메인
소규모 사업자의 경영 고민을 구체화하고 실행을 돕는 비즈니스 코칭. 사용자의 노션에 정리된 하루질문 OS(체크인·언어화·압축·최소 행동·회고)를 구현 기준으로 삼으며, 첫 실험 범위는 서비스업 매출 고민이다.

## 현재 문제
핵심 문제는 정보 부족만이 아니라, 무거운 감정과 여러 고민이 섞여 오늘 할 일을 선택하기 어렵다는 것이다.

대표의 첫 표현은 '매출이 줄었다', '광고를 늘려야 하나'처럼 포괄적이다. 해결 행동을 선택하려면 비교기간, 유입, 전환, 객단가, 재구매 정보를 추가로 확인해야 한다. 기존 일반 프롬프트는 이런 확인 없이 일반적인 조언을 생성할 수 있다. 실제 소요시간과 발생 빈도는 아직 측정하지 않았다.

## 개선 가설
고민 해석 단계에 텍스트 생성 모델을 넣고, 감정 체크인 → 판별 질문 → 근거와 가설 분리 → 우선순위 하나 → 오늘 30분 이내 첫 행동 → 저녁 회고의 순서를 강제하면 일반 프롬프트보다 근거 일치성과 행동 구체성이 개선될 것이다. LLM 호출 코드 및 체험 흐름은 이 가설을 기준으로 구현했다.

## 대상 사용자
비즈니스 코치 및 경영 고민을 혼자 정리하는 소규모 서비스업 대표. 첫 시험 참여자는 본인이 될 수 있다.

## 성공 기준 (모두 사전 목표, 아직 미측정)
- 동일 모델·동일 정보의 일반 프롬프트 대비 10점 품질척도 평균 +2점.
- 근거 없는 사실/수치 생성 0건.
- JSON 응답 형식 성공률 95% 이상 (6건 시험에서는 표본 부족을 함께 보고).
- 사용자가 5분 이내 오늘 30분 이내 시작·완료할 행동 1개 작성. 사용성 실험에서 별도 측정.
- 실제 매출 개선은 본 과제의 단기 성과로 주장하지 않음.

## 필요한 실제 데이터
사용자 본인의 최근 매출 관련 고민 1~3건과 당시 알고 있던 정보/제약을 익명화하여 준비해야 한다. 이름, 고객정보, 상호, 전화번호와 민감한 금액은 공개하지 않는다. 공개용 익명화 이후 사실 관계가 바뀌었다면 변경 범위와 한계를 명시한다.
현재 포함된 examples.json 및 cases.json은 모두 합성 데이터로 실제 도메인 실험을 대체하지 않는다.

## 모델 선정
텍스트 생성 모델: 한국어 자유 서술 이해·질문 생성·결과 구조화에 적합한 후보로 GPT-4.1 mini를 구현.
후보 비교: 규칙 기반 체크리스트는 저렴하고 재현이 쉽지만 자유 서술과 다양한 맥락 반영에 한계. STT는 음성 입력이 주요 병목일 때 유용하나 현재 입력이 텍스트여서 우선순위 낮음. YOLO/SAM은 시각 대상 분석이 필요한 과제가 아니므로 제외. Diffusion은 진단 문제와 직접 관련 없음.
수업에서 실제 배운 텍스트 생성 모델명을 확인해야 한다. 위 후보를 배우지 않았다면 수업 모델로 교체하고 호출 형식 및 결과를 재검증한다.

## 변경 기록
v0.1: 평가표 기반으로 매출 하락 진단에 범위 한정.
v0.2: 과제 원문 확인 후 실제 도메인 데이터 1건 이상 실행을 필수 게이트로 명시. 웹 배포보다 실행·비교 증거를 우선.

v0.3: 노션 원안 확인 후 하루질문 OS의 5단계로 수정. 7일 과제를 오늘 30분 이내 첫 행동으로 축소하고 장애물·저녁 회고를 다음 질문에 연결.
