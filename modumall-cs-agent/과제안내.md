# 과제: 모두몰 고객 응대 에이전트

모두연 LangGraph 수업(1~9강) 과제입니다. 가상 쇼핑몰 '모두몰'의 고객 문의를 유형별로 나누고, 어드민 데이터를 조회한 뒤, 업무 매뉴얼에 근거한 답변만 내보내는 에이전트를 만듭니다. 근거 없는 숫자가 섞이거나 애매한 문의는 사람 상담원에게 넘깁니다.

- 제출 저장소: [modulabs-assignments/modumall-cs-agent](https://github.com/daum0809/modulabs-assignments/tree/main/modumall-cs-agent)
- 커리큘럼·구조 설명: [CLAUDE.md](CLAUDE.md), 결과 요약: [README.md](README.md), 실패 분석: [실패분석.md](실패분석.md)

```
START → route ─┬─(확신도 ≥ 0.7)→ answer → guard ─┬─(통과)→ END
               └─(확신도 < 0.7)→ escalate        └─(실패)→ escalate
```

## 1-1. 카테고리 설계

**나눈 기준**: 고객이 *무엇을 하려는지*(행동)와 *어느 정책 문서로 답할 수 있는지*(근거)가 같은 문의끼리 묶었습니다. 한 카테고리는 근거 문서 하나와 1:1로 대응합니다.

| 카테고리 | 고객의 의도 | 근거 문서 (프롬프트에 넣는 것) | 조회 도구 | 나눈 이유 |
|---|---|---|---|---|
| `delivery` 배송 | 언제 오는지, 배송비가 얼마인지 | `delivery.md`: 배송비, 무료배송 기준, 도서산간 추가비, 출고 기간, 배송 조회 | `get_order`, `get_shipping_fee` | 주문 상태·금액 조회가 필요한 유일한 정보성 문의 |
| `return` 반품·교환 | 받은 상품을 돌려보내거나 바꾸기 | `return.md`: 신청 기간, 단순변심·불량 배송비, 환불 시점 | `get_order` | 배송비 부담 주체가 배송 문의와 정반대라 섞이면 오답 |
| `bundle` 세트 상품 | 세트 상품의 반품·교환·할인 | `bundle.md`: 부분 반품 불가, 불량 구성품 교환, 세트 할인 | `get_order` | 일반 반품 규칙과 **충돌**하는 예외 규칙이라 따로 분리 |
| `order` 주문·결제 | 출고 전 주문 바꾸기·취소, 결제 | `order.md`: 출고 전 취소, 출고 후 반품 전환, 카드 취소 반영, 배송지 변경 | `get_order` | "배송"이라는 말이 나와도 출고 전 변경은 주문 문제 |
| `other` 기타 | 위 어디에도 속하지 않는 문의 (항의, 보상, 연락처, 탈퇴 등) | **없음** | 없음 | 근거 문서가 없으므로 답하지 않고 **항상 사람에게 이관** |

- 매핑은 `config.py`의 `ROUTE_MANUALS`에 정의되어 있고, `tools/manuals.py`가 매핑된 문서 **하나만** 읽어 답변 프롬프트에 넣습니다.
- 한계: 두 카테고리에 걸친 문의(예: 세트 반품 + 반품 기간)는 한쪽 근거만 들어가 일부를 답하지 못합니다. [실패분석.md](실패분석.md) 3장 q04.

## 2. 실행 방법

이 폴더(`과제_모두몰고객응대에이전트`)에서 실행합니다. 가상환경은 상위 폴더의 `.venv`를 함께 씁니다.

```bash
..\.venv\Scripts\python -m unittest discover -s tests -t .                 # 테스트 18개 (API 키 불필요)
..\.venv\Scripts\python -m eval.validate_scorer                            # 채점기 타당성 확인 (키 불필요)
..\.venv\Scripts\python -m eval.score_router --router rule --set test      # 규칙 라우터 (키 불필요)
..\.venv\Scripts\python set_key.py                                         # API 키를 화면에 안 보이게 입력
..\.venv\Scripts\python -m eval.score_router --router llm --set test       # LLM 라우터
..\.venv\Scripts\python -m eval.score_pipeline --router llm --set test     # 전체 파이프라인 (답변은 eval/results/에 저장)
..\.venv\Scripts\python graph.py "MD-1001 언제 와요?"                       # 질문 하나 실행
```

`--set dev`는 개발셋(튜닝하며 본 14문항), `--set test`는 테스트셋(튜닝에 쓰지 않은 12문항)입니다.

## 3. 결과

최종 결과 (2026-11-02):

| | 개발셋 (14) | 테스트셋 (12) |
|---|---|---|
| 규칙 라우터 정확도 / Macro F1 / 이관 판정 | 0.857 / 0.836 / 9 | 0.833 / 0.820 / 8 |
| LLM 라우터 정확도 / Macro F1 / 이관 판정 | 0.857 / 0.836 / 13 | 1.000 / 1.000 / 11 |
| 전체 파이프라인 통과 (R1~R5 모두) | **12/14** | **12/12** |

테스트셋은 12문항이라 한 문항이 8%p입니다. 실패 원인과 읽어 보고 찾은 문제는 [실패분석.md](실패분석.md).

개발셋으로 전체 파이프라인을 9/14 → 11/14 → 12/14로 올린 과정:
1. 도구 설명의 예시 주문번호 `MD-1001`이 고객 답변에 새어 나옴 → 가드가 차단 → 도구 설명에서 숫자 예시 제거
2. "배송지 변경"을 배송으로 분류 → 라우터 프롬프트에 "배송지 변경은 주문" 규칙 추가
3. 가드가 "5만 원"과 "50,000원"을 다른 숫자로 봄 → 만·천 단위 해석 추가
4. 모델이 "총 6,000원"처럼 합계를 만듦 → 가드는 엄격하게 두고 답변 프롬프트에서 합계 계산 금지

남은 2건: q08(분류는 맞지만 확신도 0.6으로 과잉 이관), q14(반품·세트가 섞인 애매한 문의, 안전하게 이관).

## 4. 회고

- **도구 설명도 프롬프트다.** 개발자용으로 적은 예시가 고객 답변으로 새어 나올 수 있다.
- **정확도보다 이관 판정이 중요할 수 있다.** 규칙 라우터는 F1이 더 높았지만 틀린 답을 확신도 1.0으로 내보냈다. LLM 라우터는 틀릴 때 확신도를 낮춰 사람에게 넘겼다.
- **가드는 엄격하게, 고치는 건 답변 쪽에서.** 오탐이 나와도 검사를 풀지 않고 프롬프트로 출처 없는 숫자를 만들지 않게 했다.
- **LLM은 같은 질문에도 매번 조금씩 다르게 답한다.** 한 번 채점한 점수는 1~2문항 흔들릴 수 있다.

이 과제의 구조(그래프·가드·채점)는 그대로 두고, **업무 내용만** 학원 것으로 바꿉니다.
연습용으로 한 번 바꿔 본 결과가 `academy-cs-agent`(별도 비공개 저장소, 작업 폴더에서는 `../academy-cs-agent/`)에 있으니, 막히면 같은 파일을 비교해 보면 됩니다.

| 순서 | 바꿀 파일 | 쇼핑몰 (지금) | 학원 (바꿀 내용) | 연습 버전에서 참고할 곳 |
|---|---|---|---|---|
| 1 | `config.py` | 라우트 5개 (배송·반품·세트·주문·기타) | 학원 문의 유형 (학원비·시간표·결석·조퇴·보강·성적상담·등록·레벨테스트·인사·기타) | `academy-cs-agent/config.py` |
| 2 | `data/manuals/` | 쇼핑몰 매뉴얼 4개 | **우리 학원 실제 규정** (수강료, 환불, 보강, 결석, 레벨테스트 등) | `academy-cs-agent/data/manuals/` |
| 3 | `data/admin_db.json` | 주문 3건 | 원생 정보 (연습은 가짜 원생으로) | `academy-cs-agent/data/academy_db.json` |
| 4 | `tools/` | 주문 조회, 배송비 계산 | 원생 조회, **환불액 계산**, 결석·조퇴 접수, 보강 시간 조회 | `academy-cs-agent/tools/academy.py` |
| 5 | `routers/` | 쇼핑몰 키워드·분류 규칙 | 학원 키워드·분류 규칙 | `academy-cs-agent/routers/` |

| 8 | 채점 | — | 규칙 라우터 기준선 → LLM 라우터 → 전체 파이프라인 순서로 다시 채점 | 이 문서 2장 |

바꿀 때 지킬 점:
- **환불액·금액은 도구가 계산**하고 모델은 옮기기만 한다. 모델이 직접 계산하면 가드에 걸린다(위 4장 세 번째 교훈).
- 도구 설명(docstring)에 **숫자 예시를 쓰지 않는다**(위 4장 첫 번째 교훈).
- 평가셋은 **규칙을 만들기 전에** 먼저 고정한다. 평가셋을 보면서 키워드를 만들면 점수가 부풀려진다(연습 버전 규칙 라우터 1.000이 그 예).
- 실제 원생 정보를 쓰기 전에 **문의한 사람이 보호자인지 확인**하는 단계를 넣는다.
- 실제 원생 데이터와 `.env`는 GitHub에 올리지 않는다.
