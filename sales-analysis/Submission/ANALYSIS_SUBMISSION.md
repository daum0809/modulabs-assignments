## 1. 샘플 데이터와 정답 계산
| 파일 | 내용 |
|---|---|
| `data/sales_2026_06.csv` ~ `sales_2026_09.csv` | 가상 쇼핑몰 4개월 매출 (월 300행, 총 1,200행) |
| `data/answer_key.json` | 코드로 대조하는 정답표 |
| `tools/generate_sales.py` | 데이터 생성 스크립트 (고정 시드라 다시 돌려도 같은 파일이 나옴) |

데이터 설정
- 가상 업체: 코스트코 건강보조식품을 온라인으로 파는 쇼핑몰. 판매 채널 쿠팡, 네이버스토어, 자사몰. 제품 20종
- 한 행 = 1주 구간 × 채널 × 제품 (한 달 5구간 × 3채널 × 20제품 = 300행)

숨겨 둔 정답
- 9월 초 쿠팡에 경쟁 셀러가 나타나 우리 인기 제품 8개를 9~13% 싸게 팔았다. 운영자는 가격을 맞추지 않고 쿠팡 광고비를 약 50% 늘렸다. 방문은 유지됐지만 쿠팡 구매전환율이 5.16% → 2.43%로 떨어져 9월 매출이 31.5% 줄었다.
- 전체 하락액의 92.7%가 쿠팡, 그중 경쟁가가 붙은 8개 제품이 76.4%
- 함정 변수: 추석, 공휴일, 품절, 할인. AI가 이것을 주원인으로 지목하면 오답
- 경쟁가와 전환율 하락은 시점이 겹칠 뿐 인과를 확정할 수 없음. AI가 이 한계를 말해야 함

대표 정답 (6~9월 파일 4개를 모두 올렸을 때)

| 항목 | 정답 |

| 9월 매출 | 27,356,180원 (전월 대비 -31.45%) |
| 9월 광고비 | 6,928,570원 (+23.07%) |
| 9월 ROAS | 3.95배 (-44.30%) |

| 쿠팡 9월 ROAS | 2.97배 |
| 쿠팡 경쟁가 열세 제품 | 8개 |

## 2. 지원 / 미지원 분석

### 지원
| 분석 | 설명 |
|---|---|
| 월별 지표 | 매출, 광고비, 방문, 구매 등 합계와 CTR, CVR, ROAS, CPA, 객단가 등 비율 (계산식은 PRD §6) |
| 전월 대비 증감률 | 매출, 광고비, 방문, 구매, ROAS, CVR, CPA, 객단가 |
| 판매 채널별 지표 | 채널마다 월별 지표 |
| 쿠팡 경쟁가 진단 | 이번 달 쿠팡에서 경쟁 최저가가 우리 판매가보다 낮은 제품 목록 |
| AI 해석 | 위 계산 결과를 받아 확인된 사실, 원인 후보, 다음 행동, 분석 한계로 나눠 설명 |

### 미지원
| 분석 | 이유 |
|---|---|
| 상품별 지표 | 계산 코드가 상품별로 묶어 계산하지 않음 |
| 주별, 일별 추이 | 월 단위로만 묶음 |
| 쿠팡 외 채널의 경쟁가 진단 | 진단 기준이 쿠팡으로 정해져 있음 |
| 두 데이터셋 결합, DB 직접 연결, 분석 코드 실행 | 만들지 않음 |

## 3. 전처리 규칙
대시보드에서 CSV를 올릴 때 적용합니다.

| 규칙 | 걸리면 |
|---|---|
| 파일 확장자가 `.csv`가 아님 | "CSV 파일이 아닙니다" |
| 빈 파일, 제목 행만 있음 | "빈 파일입니다", "데이터가 없습니다" |
| 필수 열 3개(`date`, `product`, `channel`) 중 빠진 열이 있음 | 빠진 열 이름을 보여 줌 |
| 숫자 열 11개(`unit_price`, `competitor_min_price`, `impressions`, `clicks`, `visits`, `add_to_cart`, `purchases`, `units`, `revenue`, `ad_spend`, `refund`)가 하나도 없음 | 필요한 열 이름을 보여 줌 |
| 칸 수가 제목 행과 다름 | 파일명, 행 번호를 보여 줌 |
| `date`가 YYYY-MM-DD 형식이 아님 | 파일명, 행 번호, 값을 보여 줌 |
| 있는 숫자 열의 값이 0 이상의 숫자가 아님 (빈칸 포함) | 파일명, 행 번호, 열 이름, 값을 보여 줌 |
| 제목 줄이 한국어인 마켓 원본 (쿠팡, 네이버스토어 주문내역 제외) | 원본은 바로 읽지 못한다고 안내함 |

- 없는 숫자 열로 만든 지표는 0이 아니라 "계산 불가"로 보여 줍니다.
- 오류가 하나라도 있으면 그 파일은 계산하지 않습니다. 오류는 최대 5개까지 보여 줍니다.
- 파일 맨 앞의 BOM은 지웁니다. 따옴표 안의 쉼표와 줄바꿈은 값으로 읽습니다.
- 여러 파일은 행을 합쳐서 계산합니다. 파일마다 열 구성이 달라도 필수 열만 있으면 됩니다.
- **쿠팡 주문내역 원본** (`주문번호`, `주문일`, `등록상품명`, `구매수(수량)`, `결제액`이 있는 파일)
  - `주문일` → `date`, `등록상품명` → `product`, `구매수(수량)` → `units`, `결제액` → `revenue`로 읽고, 채널은 쿠팡, 주문 1건을 구매 1건으로 셉니다.
  - `주문상태`가 취소·반품인 주문은 매출에서 뺍니다.
  - 날짜의 `.`, `/`는 `-`로 바꾸고, 금액의 쉼표(`23,900`)는 지웁니다.
- **네이버스토어 주문내역 원본** (`상품주문번호`, `주문일시`, `상품명`, `수량`, `최종 상품별 총 주문금액`이 있는 파일)
  - `주문일시`의 날짜 → `date`, `상품명` → `product`, `수량` → `units`, `최종 상품별 총 주문금액`(할인 뒤, 배송비 제외) → `revenue`로 읽고, 채널은 네이버스토어, 주문 1건을 구매 1건으로 셉니다.
  - `주문상태`가 취소·반품이거나 `클레임상태`가 취소완료·반품완료인 주문은 매출에서 뺍니다. 반품요청처럼 진행 중인 것은 매출에 넣습니다.
- **하지 않는 것:** 결측치 채우기, 중복 행 지우기. 마켓 원본이 아닌 파일은 날짜 형식을 바꾸지 않고 오류로 알려 줍니다.

## 4. 데이터 흐름도

```
[사용자] CSV 올리기 (또는 예시 데이터)
   ▼
[5번 csv.js] 검사 ── 오류 ──▶ 오류 안내 (계산 안 함)
   ▼
[4번 result-engine.js] buildResult(rows) ── 지표 계산 (AI 안 씀)
   ▼
[5번 대시보드] KPI 6칸 · 월별 매출 · 구매 퍼널 · 채널별 ROAS · 쿠팡 경쟁가 진단
   ▼
[사용자] 질문 → 분석 계획 확인 → [승인]  (취소하면 AI를 부르지 않음)
   ▼
[4번 AI 서버 analyze-shop] 로그인 확인 → 하루 한도 차감 → OpenAI에 계산 결과 + 질문 전달
   ▼
[5번 답변 카드] 분석 글 표시 (실패하면 실패 이유 카드)
```

- AI에 보내는 것은 계산 결과(약 8KB)와 질문뿐입니다. 원본 CSV는 보내지 않습니다.

## 5. 실행 로그
| 언제 | 화면에 나오는 것 |
|---|---|
| 승인 전 | 계획 카드: 단계마다 할 일과 사용할 도구(계산 함수나 AI 서버) |
| 승인 후 | "✓ 계획 승인됨 · 승인 시각 · 질문" 한 줄 |
| AI 결과 | 답변 카드, 또는 실패 카드(중단, 시간 초과, 연결 실패, 로그인 필요, 오늘 한도 초과 등) |

계획 카드 예시 (질문 "광고비는 늘었는데 왜 매출이 안 늘었어?", 예시 데이터 1,200행, 9/29 5번 리허설)

| 단계 | 할 일 | 도구 |
|---|---|---|
| 1 | 올린 CSV를 합쳐 월별로 묶고, 최근 두 달(전월, 이번 달)을 비교한다 | buildResult → monthly_kpis, changes |
| 2 | 광고비 → 방문 → 구매 → 매출 순서로 변화율을 이어 보고, 가장 많이 떨어진 채널을 찾는다 | changes, channel_kpis |
| 3 | 경쟁가 진단 결과를 함께 본다 | diagnostics |
| 4 | 계산 결과만 AI에 보내 확인된 사실, 원인 후보, 실행 제안, 한계를 받는다 | AI 서버 analyze-shop |

## 6. 비용과 시간

| 측정 | 결과 | 측정 방법 |
|---|---|---|
| CSV 4개(1,200행) 읽기와 검사 | 약 9ms | 예시 데이터로 측정 |
| 지표 계산 (1,200행) | 약 2ms | 예시 데이터로 측정 |
| 지표 계산 (100,800행) | 약 68ms | 예시 데이터를 84번 이어 붙여 측정 |
| AI 분석 응답 | 8~28초 | 10/1 키 교체 후 측정 (질문 길이에 따라 다름) |
| AI 분석 1회 비용 | 약 60~170원 | 10/1 측정, 모델 GPT 5.6 sol |

- 사용량 상한: 무료 회원은 AI 분석 하루 5회 (2번 `supabase/schema.sql`)
- 대시보드는 AI 응답을 60초까지 기다리고, 넘으면 멈춥니다. 10초가 넘으면 "평소보다 오래 걸립니다"라고 안내합니다 (5번 `part5/status-card.js`)
